# Standalone example apps

Status: implemented, experimental Phase 5. Builds on decisions [0003](0003-output-and-authority.md), [0006](0006-durable-workspaces.md), and [0007](0007-content-extensions-and-setup.md).

The three independently runnable Blazor Web Apps use per-page Interactive Server, private logical workspaces, and the default `AiInput`/`AiOutput` pair. Domain behavior lives in each app. The non-packable ExampleHost Razor library shares only synthetic identity setup, optional model configuration, workspace controls, and presentation. It is example source, not a new framework dependency or production identity product.

All apps refuse to start outside Development with their synthetic account integration. Cookie names and data-protection purposes are distinct per app. Sign-in/out are static HTTP POSTs with antiforgery validation and server-allowlisted identities/roles. News/assets issue a private random owner; staff has named synthetic dispatchers/readers. Four-hour persistent cookies allow reopening a browser without immediately losing the private owner. Interactive services obtain the authenticated principal from AuthenticationStateProvider; production account lifecycle/revalidation remains a consuming-host responsibility.

Gaming News uses an explicit INewsSource. Its default data is fictional and attributed; a host can configure a fixed HTTPS JSON feed without introducing external search into core. Bounded parsing rejects malformed/ambiguous records and unsafe source links. Owner-scoped bookmarks and immutable comparison snapshots preserve date, source, versions, and tips even when an article disappears from the current feed. Citation links are an example-owned registered renderer. Preferences prioritize a game on the next request rather than silently removing selected records.

Staff Business owns an EF Core SQLite database with a new factory-created context per operation. Jobs, staff, operation history, and transactional idempotency receipts are separate from framework checkpoint tables/files. Assignment writes recheck the trusted actor/role, validate values, and use an application-managed concurrency token. A conflicting save retains the private draft. Refreshing/reconnecting obtains current records; rebasing the expected version is an explicit local action after review. Readers are denied in both the proposed-UI path and the application service. EnsureCreated initializes this small example; production migrations and provider replacement belong to the application.

Asset Workbench composes the public content services and image-editor pack with an example-owned typed version-picker renderer. The picker resolves retained parent metadata, reports live dimension groups, and selects original/working references through validated local events. Resizing remains the pack's registered action and creates actual immutable PNG bytes. Original recovery and choosing another version are local presentation changes; downloading reauthorizes the current HTTP identity. Procedural samples are original MIT assets.

Fixture mode uses authored documents and real domain operations, with no model inference. Optional model mode uses the existing adapters and app data sources; initialization/restoration still does not invoke a model. Neither mode turns generated output or feed/file content into authority. Live-provider evaluation remains deferred. The only ordinary-renderer adjustment is accurate draft wording when one action has saved while other fields remain dirty; no public framework contract changes were needed.

Acceptance evidence is recorded in the [Phase 5 guide](../phase-5-example-apps.md) and [test matrix](../../tests/README.md). No packages or website are publicly released by this phase.
