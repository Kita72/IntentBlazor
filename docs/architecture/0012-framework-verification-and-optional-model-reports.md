# Framework verification and optional model reports

Status: accepted by Tory on November 4, 2026. Supersedes the mandatory live-provider and native-model-read release gates in decisions [0010](0010-preview-release-gates.md) and [0011](0011-provider-workflow-evaluation.md). Provider adapters, evaluation procedures and the two-component developer contract remain available.

IntentBlazor supplies reusable connections, configurable capabilities, C# tool registration, validated output, protected state and rendering. Application developers choose models, credentials, endpoints, supported settings and business services. They evaluate model quality, hardware suitability, latency, cost and their application's workflows. A framework release does not require maintainers to run local or paid inference or certify a particular model.

Framework behavior still requires offline verification: actual SDK request serialization against scripted HTTP handlers, tool routing, structured-output parsing, validation and rejection, cancellation, budgets, errors, state/draft recovery, authorization and deterministic rendering. Verification also builds/runs independent package consumers and audits packages/symbols. Public setup must expose supported primitives and make unsupported capabilities explicit, without promising universal model compatibility or adding parameters to default AiInput/AiOutput.

ReleaseReadiness keeps runtime, package, NuGet policy and public-host checks as mandatory gates. The publishing workflow still runs complete deterministic verification before checking readiness and requesting credentials. Provider and native-tool reports become optional ProviderObservations; missing, old, failed or unreadable reports cannot block framework publication or be described as successful. A complete profile observation retains the exact source, protocol, model identity and six-workflow criteria. Optional native-tool observations remain distinct from preload results. Strict report readers still reject malformed evidence; the readiness reader treats it as unverified optional input.

Live diagnostics remain opt-in tools for developers and contributors, separate from build, test and publication. Existing historical failures remain intact. The maintainer does not need to complete them as deferred milestone work. Codex remains an experimental independent preload-only process adapter, with no connection to this desktop chat or its authority; it is documented without a live certification claim.

Do not start Ollama, LM Studio or their model workers on Tory's current machine, including status commands that can activate a service. Those installations are reserved for Tory's own testing. Use offline HTTP/process/model substitutes; do not run paid OpenAI/Codex inference. A future live run requires a new explicit user decision and a suitable host. These restrictions are independent of whether live reports are release gates.

Package publication, account-policy confirmation, deployment and release tagging remain separate maintainer tasks. This scope change does not mark the candidate published or any unperformed browser, hosting or compatibility check complete.
